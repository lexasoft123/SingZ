## Per-frame allocations and text shaping found

- The lyric player layout shapes every word with `shape(...)` and builds `Vec` rows/words plus owned strings on a width-key cache miss; cache is retained and keyed by rounded width. Per rendered frame it also shapes the baseline, and active-line scale metrics when the active line is started (`src/main.rs:4550-4605`, `src/main.rs:4720-4740`). This is conditional shaping, not every frame for all words.
- Lyrics render clears and refills the `layout` vector for visible paragraph bounds each render, and may allocate countdown sprite text via `cue.kind.text()` (`src/main.rs:4738-4740`; `src/lyrics_countdown.rs:12-17`).
- Pitch strip paint shapes labels through `text()` / `shape_line`; labels include formatted note and time strings in the paint path (`src/pitch_strip.rs:582-600`, `src/pitch_strip.rs:697`, `src/pitch_strip.rs:810-840`, `src/pitch_strip.rs:970-1028`). Per-frame frequency depends on parent redraw; formatted labels are transient allocations.
- Lyrics editor builds row/control IDs with `format!` and shapes each visible word via `shape_line` during render (`src/lyrics_editor.rs:381-390`, `src/lyrics_editor.rs:438-452`). These allocations/shaping recur whenever editor redraws; no frame cache is evident at these sites.
- `pitch_strip` mic trail is preallocated with capacity 1024 at construction (`src/pitch_strip.rs:70`); trail updates are change-driven rather than allocating a fresh buffer per paint.

## Fencing vocabulary

| Fence | GPUI helper | Box/session side |
|---|---|---|
| `generation` | Song playback uses helper `generation` and incrementing `nextGeneration`; cue transactions independently require positive, increasing `cueGeneration` (`tools/native/singz-gpui-audio.cpp:73-78,1385-1392`; playback transition `tools/native/singz-gpui-audio.cpp:1270-1287`). | Session rejects zero/stale generations, tracks pending/active/retiring/swap generations, and fences transport mailbox commands (`native/playback/native_playback_session.cpp:851,6008-6023,6124-6207,8191-8205`). Monitor API calls carry `ownershipGeneration` (`native/electron/audio_monitor_session.h:43-67,117-123`). |
| `serial` | No per-command serial is visible in helper command framing; the command line is parsed and handled synchronously (`tools/native/singz-gpui-audio.cpp:970-984`). | Internal audio-host coordination has session serial fields and command identity (`native/playback/native_playback_session.cpp:4731-4766,5495-5496`). **Not the public ownership fence** (inferred from call sites). |
| `instance` | No explicit backend-instance token crosses helper protocol; helper owns process-level service/backend objects (`tools/native/singz-gpui-audio.cpp:970-984`). | `AudioHostBackend` is an owned polymorphic backend object with open/start/stop/status and suspend/resume operations (`third_party/zcore/zcore/include/zcore/device/audio_host.h:235-281`). ## Difference in responsibilities

- **Helper-only:** ASCII stdin/stdout protocol, bounded command parsing, multi-line atomic cue/lane/carry/metronome drafts, process `quit`, provider selection/scope, pinning and retaining source descriptors, park/unpark policy, and user-facing orchestration across playback and training. These are helper responsibilities visible in its command loop and supporting protocol code (`tools/native/singz-gpui-audio.cpp:7-9,1093-1169,1316-1550`; provider wrapper `tools/native/gpui_audio_provider.h:112-175`).
- **Session-only:** host/backend ownership and replaceability, callback-safe prepared-graph lifecycle, generation validation across async prepare/swap/unload, transport command fencing, detailed teardown certainty/quarantine, and session status/position telemetry (`native/playback/native_playback_session.h:896-907`; `native/playback/native_playback_session.cpp:6008-6207,7319-7485,7681-7872,8669-9053`).
- **Already close at the host seam:** the GPUI provider header constructs platform-specific `AudioHostBackend` values and wraps provider scope (`tools/native/gpui_audio_provider.h:112-175`); `NativePlaybackSession` accepts an owned `AudioHostBackend` (`native/playback/native_playback_session.h:896-907`). The helper already creates a GPUI-selected, scoped `AudioHostBackend`, passes it to `SharedAudioService`, then constructs `NativePlaybackSession` from `service->playbackBackend(...)` (`tools/native/singz-gpui-audio.cpp:680-692`). The helper is therefore already on the session seam for playback; remaining difference is its outer line protocol and helper-owned orchestration/lifecycle policy (inferred).

The Box host contract is a backend abstraction: enumerate/describe, open with callback/config, start, stop, status, and optional suspend/resume (`third_party/zcore/zcore/include/zcore/device/audio_host.h:235-281`). The Box `AudioMonitorSession` consumes that interface and exposes generation-fenced begin/setGain/end plus status; it is a monitor owner, not itself the playback session (`native/electron/audio_monitor_session.h:104-127`).

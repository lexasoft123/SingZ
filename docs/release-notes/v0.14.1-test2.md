v0.14.1-test2 — Test build: GPU splitting in smaller bites

Second test build for the GPU splitter. The first one proved the splitter now
finds the right GPU — and that the graphics driver still gives up on the
first chunk. The suspect: the whole model runs as one giant GPU command, and
Windows shoots any command that takes longer than two seconds. This build
retries automatically with the model split into many small commands — slower
per chunk, but each piece is far under the limit — before falling back to
CPU as always.

To test it: install, open the model manager (the splitter chip), switch to
GPU, and split a song that hasn't been split before. The log now shows a
second attempt line — "trying ONNX provider: dml (graph fusion off)" — after
the first one fails. Save the log (Log dialog → Save) and send it over,
success or not. If it works, the interesting number is the seconds per chunk
compared with the CPU run.

Everyone else: nothing to see here — single-GPU machines and the regular
update channel are untouched.

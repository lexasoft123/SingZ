v0.17.1 — the Windows build comes back

<!-- store:en-US -->
Nothing in the Android app changed in this one. It exists because the Windows half of 0.17.0 never got built: one test in our own suite made an assumption that only holds on a Mac, the Windows job stopped there, and the installer and the Windows stem-splitter download were never published. Both are back. If you are on Android you already have everything 0.17.0 brought — the phone working out beat, key and melody on its own, and songs compacting themselves — and this changes none of it.

Windows:

- **0.17.0 exists for you now.** The Windows installer never made it into
  0.17.0, so there was nothing for your machine to update to. It is here.
  What you get is everything 0.17.0 described for Mac and Windows: a song
  tagged with a "feat." credit, or ripped with a download site stuck in front
  of the artist, now finds its synced lyrics instead of sending the app off to
  transcribe something that was already timed by hand; lyrics can no longer
  land in the song you switched to while they were loading; and cancelling a
  Precise alignment stops writing itself into the log as an error.

- **And the stem splitter can be downloaded again.** This is the part worth
  apologising for. The app builds that download link from whichever release is
  newest, not from the version you are running — so when 0.17.0 went out
  without a Windows splitter pack, the link broke for **everyone** on Windows,
  including people still on 0.16.2 who had never installed 0.17.0 at all. If
  you tried to set up splitting in the last little while and it failed, that
  was this, it was not your machine, and it works now.

Mac, iPhone and Android: nothing whatever changes for you here — 0.17.1 is
0.17.0 with a Windows installer beside it. Your Mac will offer the update
anyway and there is no harm in taking it; it is the same app.

What actually broke, since it is a good story about tests: 0.17.0 made every
spawned engine wait for its output to arrive rather than merely for the
process to end, with a grace timer so a stray descendant holding the pipe open
can never hang the app forever. The test that proves the grace timer works
spawns a child that leaves a grandchild holding the pipe, and checks that the
handler waited. On a Mac it waits, because that is what inheriting the pipe
does there. On Windows, CI measured the same case settling in 110
milliseconds with the output whole and correct: the wait never happened,
because there was nothing to wait for. The code was right on both; the test
was asserting a Mac's plumbing as though it were a rule. It now asserts the
outcome everywhere and the timing only where the pipe is provably held open.

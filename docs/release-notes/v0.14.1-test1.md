v0.14.1-test1 — Test build: the splitter picks the fast GPU itself

This is a test build for laptops with two GPUs (one battery-saving, one for
games). The splitter's GPU engine used to land on whichever GPU drives the
screen — on gaming laptops that's the slow battery-saving chip, which gave up
mid-song while the fast GPU sat completely idle. The splitter now looks at
every GPU in the machine, writes what it found into the log, and runs on the
most capable one.

To test it: install, open the model manager (the splitter chip), switch to
GPU, and split a song you haven't split before. Then save the log (Log
dialog → Save) and send it over — it now lists your GPUs and says which one
was chosen, and a GPU that hangs is reported as exactly that instead of a
generic error. Both "it worked" and "it didn't" logs are useful.

Everyone else: nothing to see here. This changes nothing on single-GPU
machines, and the regular update channel skips test builds entirely.
